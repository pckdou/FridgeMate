## 2. 문제 정의 및 동기 (Why)

### 문제

- 자취생은 장을 본 뒤 냉장고에 무엇이 있는지 정확히 기억하지 못해, 같은 재료를 또 사거나 가진 재료로 할 수 있는 요리를 떠올리지 못합니다.
- "대파가 남았는데 뭘 해 먹지?"처럼 재료에서 출발해 간단한 요리를 찾고 싶어도, 기존 레시피 검색은 자취생이 만들기 쉬운 요리를 우선해 보여주지 않습니다.
- 레시피를 볼 때마다 "이 재료가 집에 있었나?"를 냉장고를 열어 확인해야 합니다.

### 기존 방식의 한계 (가설, W1~2에 경쟁 서비스 조사로 검증·보완)

- 재고 관리 앱은 **재료를 하나씩 수동 입력**해야 해서 꾸준히 쓰기 어렵습니다.
- 레시피 앱은 **내 재고를 보여주지 않고**, 재료 기준 검색 결과가 난이도·재료 수와 무관하게 나열됩니다.

### 해결 접근

**영수증 사진 1장(또는 직접 등록) → 카테고리로 정리된 내 재고 → 요리/재료 검색과 자취생 Top3 → 레시피를 보면서 내 재고 확인**으로 "입력 부담", "무엇을 만들지", "집에 뭐가 있는지"를 한 흐름으로 해결합니다.

레시피와 재고를 자동으로 판정하는 대신 **한 화면에 나란히 보여주고 사용자가 확인**하도록 하여 자동 매핑의 오판 위험을 피합니다.

### 성공 지표 (목표치, W6 OCR 기술 검증과 W15 사용자 테스트 결과에 따라 조정)

| 지표 | 목표 | 측정 방법 |
|---|---|---|
| 영수증 상품명·구매일 추출 정확도 | 85% 이상 | 샘플 영수증 20장(개인정보 제거) 기준 자동 평가 스크립트 |
| 비식품 라인 제외 정확도 | 90% 이상 | 같은 샘플에서 라벨 대비 평가 |
| 영수증 1장 등록 소요 시간(확인·수정 포함) | 60초 이내 | 사용자 테스트(W15) |
| 재료 검색 Top3 만족도 | 5점 척도 평균 3.5 이상 | 사용자 테스트 설문(W15), 검색 실패 사례 수집 |
| 테스트 커버리지 | 80% 이상 | CI 커버리지 게이트 |

## 3. 핵심 기능 3개

### ① 재고 등록 (영수증 스캔 + 직접 등록)

- **영수증 스캔**: 사진에서 **상품명과 구매일만** 추출하고 수량은 등록하지 않습니다. 비식품 라인(봉투, 세제 등) 제외와 상품명 정제(접두어·중량 표기 정리)를 규칙 기반으로 처리하고, **원문(예: "풀)두부300g")은 보존**합니다. 확인 화면에서 사용자가 이름을 수정하고 항목을 제외한 뒤 저장하며, 구매일 인식 실패 시 업로드일로 대체합니다.
- **직접 등록**: 영수증 없이 이름을 입력해 등록합니다(수량은 선택 입력). OCR이 실패해도 서비스가 동작하는 기반입니다.
- 원본 영수증 이미지는 서버에 저장하지 않고 처리 후 폐기합니다.

### ② 사용자 정의 카테고리 & 내 재고 관리

- 양념, 육류, 채소 등 **기본 카테고리를 제공**하고 사용자가 추가·이름 변경·삭제합니다. 카테고리를 삭제하면 소속 재고는 '미분류'로 이동합니다.
- 카테고리별 접기/펼치기와 재고 이름 검색을 제공합니다. 같은 이름의 재고를 다시 등록하면 이전에 고른 카테고리를 자동으로 적용합니다(Should).
- 카테고리는 **표시와 정리용**이며 검색·추천 계산에는 사용하지 않습니다.

### ③ 레시피 검색 & 자취생 Top3 추천 + 레시피 화면에서 내 재고 보기

- **검색 모드 선택**: 사용자가 `[요리 | 재료]` 모드를 직접 고릅니다. 요리 모드는 레시피 제목을 검색해 목록을 보여주고, 재료 모드는 레시피 재료 텍스트를 검색해 **자취생 친화도 점수 기준 Top3**와 선정 근거(예: "재료 5개 · 4단계")를 보여줍니다.
- **동의어 확장**: "계란/달걀", "대파/파" 같은 소규모 동의어 목록(`synonyms.json`, 20~30개로 시작, 100개 이내 관리)으로 **검색어만 확장**합니다. 입력용 표현과 검색용 표현을 분리해 "파"가 "양파·파프리카"에 잘못 걸리지 않게 하며, 데이터 자체는 변경하지 않습니다. 목록은 PR로 누구나 개선할 수 있고 CI가 스키마를 검증합니다.
- **자취생 친화도 점수**: 데이터에서 항상 계산되는 재료 수·조리 단계 수를 기본으로 하고, 인분·조리 시간 정보가 있으면 추가 반영합니다. 점수 내림차순, 동점이면 레시피 id 오름차순으로 결과를 결정적으로 유지합니다.
- **내 재고 함께 보기**: 레시피 상세에서 같은 화면(데스크톱은 스크롤을 따라오는 사이드 패널) 또는 스크롤(모바일)로 카테고리별 내 재고를 확인합니다. 레시피와 재고의 비교는 사용자가 직접 합니다.

### 설계 원칙 (ADR로 기록할 핵심 결정)

- **자동 매핑 대신 사용자 확인**: 레시피 재료와 재고를 자동으로 연결·판정하지 않아 오판을 피하고, 영수증 원문은 보존하며 사용자 확인 후 저장합니다.
- **동의어는 검색어 확장 전용**: 같은 재료의 표기 차이만 수록하고(대체 재료·상하위 개념은 제외) 데이터는 변경하지 않으며, 모호한 짧은 입력은 검색 규칙으로 보호합니다.
- **결정적 결과**: 같은 입력이면 같은 Top3가 나오도록 점수 계산과 정렬 기준을 고정해 테스트 가능성을 확보합니다.

### 데이터 모델 (초안)

```
stock_items (id, user_id, raw_name, display_name, category_id?, purchased_at, quantity?, source: receipt | manual)
categories  (id, user_id, name, order, is_default)
recipes     (id, title, ingredients_text, steps, ingredient_count, step_count, servings?, cook_time?, source)
data/synonyms.json  [{ canonical, inputs[], matches[] }]   ← 입력용 / 검색용 표현 분리, zod 스키마 검증
```

## 4. 기술 스택

| 영역 | 선택 | 선정 이유 |
|---|---|---|
| 언어/런타임 | TypeScript (strict), Node.js 20 | 수업 지원 런타임(Node.js 18+) 충족, 타입 안정성 |
| 프론트엔드 | Next.js (React) + Tailwind CSS, PWA | 모바일 카메라 촬영·업로드, 모드 토글·재고 패널·하단 시트 UI에 적합 |
| 백엔드/검증 | Next.js Route Handlers + zod | AI 출력 JSON, 입력값, 동의어 파일을 스키마로 검증 |
| DB/인증 | PostgreSQL(Supabase) + Prisma, Supabase Auth | 무료 티어, 마이그레이션 관리 용이, 사용자별 재고·카테고리 저장 |
| OCR/AI | 1순위: 멀티모달 LLM API(영수증 → 상품명·구매일 JSON) / 대안: Naver Clova OCR, Tesseract | W6 PoC에서 정확도·비용·한도를 비교한 뒤 ADR로 최종 결정 |
| 영수증 후처리 | 규칙 기반 순수 함수(비식품 필터, 상품명 정제, 날짜 파싱) | 결정적 로직이라 단위 테스트가 쉽고 OCR 오류를 보정 |
| 레시피 검색 | PostgreSQL 질의 + 앱 레벨 토큰 매칭, 동의어 JSON 확장, 자취생 점수 함수 | 별도 검색 엔진 없이 구현 가능, 규칙이 명확해 테스트 용이 |
| 레시피 데이터 | 라이선스를 확인한 공공데이터 등의 레시피(제목·재료 텍스트·조리 단계)를 DB에 적재 | 출처 표기와 라이선스 준수, 재료 수·단계 수는 적재 시 계산 |
| 테스트 | Vitest(단위·통합), Playwright(E2E), 외부 API mock | 커버리지 측정, CI에서 실제 API 호출 없이 재현 가능 |
| 코드 품질 | ESLint, Prettier, Conventional Commits | 수업의 린터·포매터·커밋 규칙 준수 |
| CI/CD | GitHub Actions(lint·test·coverage·build·동의어 검증), Dependabot | PR마다 자동 검증, main 병합 시 자동 배포 |
| 배포 | Vercel(Production) + Supabase | 무료 티어로 실제 운영 환경 배포 |
| 문서화/라이선스 | README, ADR, API 문서, CONTRIBUTING(동의어 PR 방법), 데모 GIF / MIT License | 평가 항목(문서화)과 필수 요소 반영 |

> ※ 가격·무료 한도·레시피 데이터 라이선스와 제공 필드(조리 시간, 인분 등)는 도입 전에 확인합니다. AI 도구(Copilot, ChatGPT 등)는 동작 원리를 이해하고 사용하며, 사용 범위를 문서에 기록합니다.

| AI API 비용·한도, 영수증 개인정보 | 저가 모델·호출 제한·캐시, CI는 mock 사용 / 원본 이미지 미저장, 로그에 민감정보 미기록, ADR로 정책 기록 |
| 기능 범위 확대 | 우선순위 구분 — **Must**: 직접 등록, 기본 카테고리, 요리/재료 검색과 Top3, 레시피 상세의 내 재고 패널 / **Should**: OCR 자동 등록, 같은 이름 카테고리 자동 적용, 반대 모드 제안, 재고 이름 클릭 검색 / **Could**: 여러 재료 동시 검색, LLM 요리 아이디어 제안, 카테고리 순서 변경 — Could부터 축소 |
